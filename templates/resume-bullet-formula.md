# Résumé bullet formula

Used in modules 09 and 11. Every module in this repo also ends with a
pre-written bullet you can paste once the work is actually done.

## The formula

```text
[Action verb] [what, specifically] using [tool or method] to [outcome], [number].
```

Four parts. If a bullet is missing one, it is weaker than it needs to be.

| part | what it does | fails when |
|---|---|---|
| **action verb** | says you did it, not that you were exposed to it | "Responsible for", "Helped with", "Assisted" |
| **what, specifically** | lets a reader picture the work | "various data tasks", "customer issues" |
| **tool or method** | matches the keywords in the posting | no tool named at all |
| **outcome and number** | proves it mattered and that you measured it | no number anywhere in the bullet |

The number does not have to be revenue. Rows, queries, accounts, tickets,
hours saved, percentage points, days shortened, people trained. Count something
real. Never invent one.

## Verbs that work

Built, wrote, automated, mapped, documented, analyzed, designed, diagnosed,
resolved, reduced, presented, delivered, migrated, integrated, trained,
onboarded.

```text
   to ______________________________, ____________.
```

## Worked example

A customer success internship bullet, before:

```text
- Responsible for helping customers with questions about the software and
  escalating issues to the technical team.
```

No verb with weight, nothing specific, no tool, no number. Rewritten:

```text
- Resolved 200+ customer support requests across 40 accounts, diagnosing
  configuration and data-import issues before escalation and reducing average
  time-to-first-response from 6 hours to under 2.
```

Same job. Same truth. The difference is that the second one can be asked about
in an interview, and every answer you give makes you look better.

A project bullet from module 09:

```text
- Built an end-to-end data pipeline in Python and DuckDB that pulls 60,000 NYC
  311 service requests from a public API, loads them into a queryable database,
  and answers 14 analytical questions in SQL, published with a README and a
  10-minute recorded walkthrough.
```

## Rewriting a customer success bullet into an SE-adjacent one

The move is to surface the technical and diagnostic parts of work you already
did, without inventing anything.

| CS phrasing | SE-adjacent phrasing |
|---|---|
| answered customer questions | diagnosed customer-reported issues, isolating configuration from product defects |
| ran onboarding calls | delivered technical onboarding for N accounts, including data import and user provisioning |
| made reports for the team | built recurring reports on account usage and support volume, used in weekly account reviews |
| worked with the product team | translated customer requirements into written technical requests for engineering |
| helped with data uploads | mapped customer CSV exports to the product's data model and resolved format and duplicate issues before load |

Rule: if the interviewer asks "tell me about that," you must be able to talk
for two minutes without hedging. If you cannot, the bullet is overstated. Fix
it now, not in the room.
