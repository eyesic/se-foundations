# Glossary

Every term defined in bold in a module, alphabetically, one line each. The
module number in brackets is where it is introduced and explained properly.

- **30/60/90 plan** - A one-page written plan for your first three months in a role, split into learning, contributing, and owning. [11]
- **401 Unauthorized** - HTTP status meaning the server could not read or accept your credentials, so it does not know who is calling; the fix is a new or corrected token. [06]
- **403 Forbidden** - HTTP status meaning the server knows who you are but this identity is not permitted to do this; the fix is scopes, roles, or permissions, not credentials. [06]
- **429 Too Many Requests** - HTTP status meaning you exceeded the rate limit; the correct response is exponential backoff, or the wait named in a `Retry-After` header. [06]
- **access token** - The short-lived credential an application uses to call an API on a user's behalf after an OAuth 2 exchange. [06]
- **account executive (AE)** - The salesperson who owns a deal and carries the quota; the SE's partner on every customer call. [10]
- **aggregate function** - a function that collapses many rows into one value: `count`, `sum`, `avg`, `min`, `max`. [03]
- **alias** - a temporary name given to a column or table with `AS`, used to make output readable and queries shorter. [04]
- **API** (application programming interface) - a documented way for one piece of software to ask another for something; the same capability as the user interface, exposed for programs. [01]
- **API key** - A long random string identifying a calling account, sent in a header or, on older APIs, as a query parameter. [06]
- **API pull** - An integration pattern in which your system asks another system's API on a schedule for what changed. [08]
- **array** - In JSON, an ordered list of values in square brackets; parses into a Python list. (06, 07)
- **assertion** - The signed XML document a SAML identity provider returns to prove who a user is. [08]
- **at-least-once delivery** - A guarantee that an event will arrive, possibly more than once, which is why webhook receivers must be idempotent. [08]
- **authentication** - proving who is making a request, usually with a token, key, or session. [01]
- **authorization** - Determining what you are allowed to do once you are known. [06]
- **authorization code** - The short-lived code an OAuth 2 provider returns after user consent, which the application exchanges for tokens. [06]
- **availability zone** - One isolated data center inside a cloud region; running across several is how a service survives one building failing. [08]
- **AWS** - Amazon Web Services, the largest of the three major cloud providers. [08]
- **Azure** - Microsoft's cloud platform, common in enterprises already standardized on Microsoft. [08]
- **back end** - the code running on the server that checks permissions, applies business rules, and talks to the database. [01]
- **base URL** - The scheme, host, and any shared prefix of an API, such as `https://api.example.com/v2`. [06]
- **batch file transfer** - An integration pattern in which one system writes a file on a schedule and another picks it up, usually over SFTP. [08]
- **bearer token** - A credential sent in the `Authorization` header as `Bearer <token>`; whoever holds it can use it, so it is treated as a password. [06]
- **BigQuery** - Google's cloud data warehouse; runs SQL close to what this repo teaches. [03]
- **body** - the data carried inside a request or response, as opposed to its headers. [01]
- **branch** - a parallel line of work in Git; `main` is the default branch. [02]
- **cardinality** - how many rows on one side of a relationship relate to how many on the other: one-to-one, one-to-many, many-to-many. [05]
- **CASE** - SQL's if-then-else expression, used to bucket values or count conditionally. [04]
- **champion** - The person inside a customer organization who wants the purchase to happen and argues for it when you are not in the room. [10]
- **client** - the software in front of the user that sends requests: a browser, a mobile app, a desktop app. [01]
- **clone** - download a complete copy of a remote Git repository, including its history. [02]
- **cloud** - computing resources rented from a provider such as AWS, Azure, or GCP, running in their data centers. [01]
- **cohort** - a group of customers defined by when they started, used to measure retention over time. [04]
- **collection** - In Postman, a saved folder of requests, usually one per product or workflow. [06]
- **column** - one field in a table, holding one kind of value for every row. [03]
- **commit** - a saved snapshot of a repository's files, with a message explaining the change. [02]
- **composite primary key** - a primary key made of two or more columns together, standard in junction tables. [05]
- **compute** - Cloud resources that run code, such as AWS EC2 instances, containers, or serverless functions. [08]
- **condition** - An `if` statement that decides whether a block of code runs. [07]
- **CRM** (customer relationship management) - the system holding sales and account data, such as Salesforce or HubSpot. [01]
- **CTE** (common table expression) - a named temporary result defined with `WITH` at the top of a query; the readable form of a subquery. [04]
- **data center** - the building full of servers that "the cloud" actually is. [01]
- **data residency** - the physical country or region where data is stored, often a legal or contractual requirement. [01]
- **data warehouse** - a separate database holding a copy of company data reshaped for analytics, such as Snowflake or BigQuery. [01]
- **database** - software whose job is storing structured data and answering queries about it quickly and safely. [01]
- **DDL** (data definition language) - the SQL that creates and changes structure: `CREATE TABLE`, `ALTER TABLE`. [05]
- **demo** - A tailored argument that the product solves a problem the customer stated, not a tour of features. [10]
- **DENSE_RANK** - a window function that ranks rows, giving ties the same number and not skipping the next value. [04]
- **deprovisioning** - Automatically deactivating a user account when someone leaves, usually via SCIM; the part of identity that security teams ask about. [08]
- **derived table** - a subquery used in the `FROM` clause as if it were a table. [04]
- **developer tools** - the browser panel (F12) for inspecting network requests, responses, and console errors. [01]
- **dictionary** - A Python structure mapping named keys to values; the shape of one JSON object and of one row of data. [07]
- **dimension table** - a table of descriptive attributes you group and filter by: customers, plans, users. [05]
- **discovery** - The call where an SE learns current state, pain, desired state, technical environment, and decision process, before demoing anything. [10]
- **DPA** - Data Processing Agreement: the contract governing how a vendor handles a customer's personal data. [08]
- **DuckDB** - a database that runs from a single file with no server, reads CSVs directly, and speaks standard SQL. [00]
- **economic buyer** - Whoever signs the contract, often not the champion and often not technical. [10]
- **ELT** / **ETL** - the process of copying data between systems: extract, transform, load, in either order. [05]
- **encryption at rest** - Data encrypted while stored on disk, typically AES-256, protecting against a stolen drive or snapshot. [08]
- **encryption in transit** - Data encrypted while moving over a network, in practice TLS 1.2 or higher. [08]
- **.env** - the conventional filename for local secrets; always listed in `.gitignore`, never committed. [02]
- **environment** - In Postman, a named set of variables such as `dev` or `prod`, each holding its own base URL and credentials. [06]
- **ERD** (entity relationship diagram) - a picture of tables and the relationships between them, with crow's-foot notation showing cardinality. [05]
- **ETL** - Extract, Transform, Load: transform data on an intermediate server before loading the finished result into a warehouse. [08]
- **exception handling** - Catching a failure with `try`/`except` and deciding what to do instead of crashing. [07]
- **exponential backoff** - Retrying a failed request after progressively longer waits, with random jitter, so many clients do not retry in unison. [06]
- **f-string** - A Python string prefixed with `f` that substitutes variable values written inside braces. [07]
- **fact table** - a table of events or measurements over time: usage events, invoices, tickets. [05]
- **foreign key** - a column holding another table's primary key value, which is how two tables are related. [05]
- **front end** - the code running in the user's browser that draws the screen and sends requests. [01]
- **function** - A named, reusable block of code defined with `def` that optionally returns a value. [07]
- **gap list** - A three-column sort of a job posting's requirements into what you have, what is adjacent, and what is genuinely missing. [11]
- **GCP** - Google Cloud Platform, the third of the three major cloud providers. [08]
- **GDPR** - The EU regulation governing personal data, covering deletion rights, processing locations, and required agreements. [08]
- **Git** - version control software that records the full history of a folder. [02]
- **Git Bash** - the Unix-style shell installed with Git on Windows; its commands match Mac and Linux. [02]
- **GitHub** - a website that hosts Git repositories and renders Markdown and Mermaid. [02]
- **.gitignore** - a file listing paths Git should not track, such as generated files, local databases, and secrets. [02]
- **GROUP BY** - the SQL clause that splits rows into buckets so an aggregate runs once per bucket. [03]
- **HAVING** - filters groups after aggregation, which is why it can reference `count(*)` and `WHERE` cannot. [03]
- **header** - Metadata attached to an HTTP request or response, such as `Authorization` or `Content-Type`. [06]
- **headers** - metadata attached to a request or response, including authentication and content type. [01]
- **host** - The part of a URL naming which server answers, such as `api.github.com`. [06]
- **HTTP method** - The verb stating what to do with a resource: GET, POST, PUT, PATCH, or DELETE. [06]
- **ID token** - The signed JSON web token an OIDC provider returns to prove a user's identity. [08]
- **idempotent** - A request with the same effect whether run once or many times; GET, PUT, and DELETE are, POST is not. (06, 08)
- **identity provider (IdP)** - The customer's system of record for logins — Okta, Microsoft Entra ID, Google Workspace — that authenticates users on your product's behalf. [08]
- **implementation specialist** - A post-sale role owning onboarding, configuration, data migration, and training; a realistic route into solutions engineering. [11]
- **informational interview** - A short, low-stakes conversation with someone already in the role you want, asked for in three sentences with no referral request attached. [11]
- **INNER JOIN** - keeps only rows that match in both tables. [04]
- **iPaaS** - Integration Platform as a Service: hosted middleware with prebuilt connectors, such as Zapier, Workato, Boomi, or MuleSoft. [08]
- **ISO 27001** - An international certification for an information security management system, often requested in European deals. [08]
- **join** - combining rows from two tables on a matching condition, usually a foreign key equal to a primary key. [04]
- **JSON** (JavaScript Object Notation) - the text format programs use to exchange structured data: objects, arrays, and simple values. [01]
- **junction table** - a table with one row per pair, used to implement a many-to-many relationship. [05]
- **LAG** / **LEAD** - window functions that read a value from the previous or next row, used for period-over-period comparison. [04]
- **learning log** - a short daily note recording what you built, what broke, and what you understood. [00]
- **LEFT JOIN** - keeps every row from the left table, with NULLs where the right table has no match. [04]
- **list** - A Python structure holding an ordered collection of values, indexed from zero. [07]
- **loop** - A `for` statement that repeats work once for every item in a collection. [07]
- **managed database** - A database the cloud provider operates for you, handling backups, patching, and failover, such as AWS RDS. [08]
- **Markdown** - the plain-text formatting used for README files: `#` headings, `-` bullets, backticks for code. [02]
- **MEDDIC** - A sales qualification framework; SEs are usually asked to fill in the metrics and the technical decision criteria. [10]
- **MRR** (monthly recurring revenue) - the predictable revenue a subscription produces each month. [03]
- **multi-tenant** - one running copy of an application serving many customers, with every record tagged by tenant id. [01]
- **natural key** - a real-world value that happens to be unique, such as an email address. [05]
- **normalization** - splitting data so each fact is stored exactly once and referenced by key. [05]
- **NULL** - the absence of a value; not zero and not an empty string, and never equal to anything, so it needs `IS NULL`. [03]
- **OAuth 2** - A framework letting a user grant an application limited, revocable access to their data in another system without sharing a password. [06]
- **object** - in JSON, a set of `"name": value` pairs inside curly braces. [01]
- **on-premise** - software installed and run on the customer's own servers rather than the vendor's. [01]
- **pagination** - Splitting a large result set into pages, addressed by page number, offset, or an opaque cursor. [06]
- **PARTITION BY** - the part of a window function that restarts the calculation for each group. [04]
- **PATH** - the list of folders a shell searches for a command; the usual reason a program "is not recognized." [02]
- **pen test** - A penetration test: a hired security firm attempts to break in and reports what they found. [08]
- **PII** - Personally Identifiable Information: data that identifies a person, whose presence changes what security reviewers ask about everything else. [08]
- **POC** - Proof of Concept: a time-boxed hands-on customer evaluation, which needs written success criteria and a decision date. [10]
- **polling** - Repeatedly asking another system on a schedule whether anything has changed, rather than being told. [08]
- **PostgreSQL** - a widely used open-source database; the SQL dialect most SaaS products use. [03]
- **Postman** - a desktop app for sending API requests by hand and saving them as collections. [00]
- **PowerShell** - the shell built into Windows. [02]
- **primary key** - the column whose value uniquely identifies one row in a table. [05]
- **principle of least privilege** - Granting every account the minimum access it needs and nothing more. [08]
- **production database** - the database serving the live product, as opposed to the analytics copy. [01]
- **provisioning** - Automatically creating and updating user accounts in an application from the customer's identity provider, via SCIM. [08]
- **pull** - bring commits from a remote repository into your local copy. [02]
- **push** - send your local commits to a remote repository. [02]
- **query** - a written question sent to a database, which returns a table of rows. [03]
- **query parameter** - A `key=value` pair in a URL query string that filters, sorts, or pages results without changing data. [06]
- **query string** - Everything in a URL after the question mark: query parameters joined by `&`. [06]
- **RANK** - a window function that ranks rows, giving ties the same number and then skipping values. [04]
- **rate limit** - A cap on how many requests you may send in a time window, advertised in response headers and enforced with 429 responses. [06]
- **RBAC** - Role-Based Access Control: permissions attach to named roles such as admin, member, or viewer, and users are given roles. [08]
- **README.md** - the file GitHub renders on a repository's front page; the first thing anyone reads. [02]
- **referential integrity** - the guarantee that every foreign key value actually exists in the table it points at. [05]
- **refresh token** - A long-lived OAuth 2 credential used to obtain new access tokens without the user signing in again. [06]
- **region** - a cloud provider's geographic location, such as `us-east-1`; relevant to data residency. [01]
- **remote** - a copy of a Git repository hosted elsewhere, usually named `origin`. [02]
- **repository** - a folder Git is tracking, together with its complete history. [02]
- **request** - a message from a client asking a server to do something: a URL, a method, headers, sometimes a body. [01]
- **response** - the server's reply: a status code and usually a body. [01]
- **REST API** - The dominant style of web API: resources addressed by URL, acted on with standard HTTP methods, usually exchanging JSON. [06]
- **RFP** - Request for Proposal: a formal document of vendor questions, whose technical sections an SE answers. [10]
- **row** - one record in a table. [03]
- **ROW_NUMBER** - a window function that numbers rows sequentially with no ties. [04]
- **running total** - a cumulative sum produced by an aggregate with `OVER (ORDER BY ...)`. [04]
- **SaaS** (software as a service) - the vendor runs the software and the customer accesses it over the internet on a subscription. [01]
- **safe** - An HTTP method that never changes data; GET is safe, POST is not. [06]
- **SAML** - An older, XML-based single sign-on protocol still standard in enterprise deals. [08]
- **scheme** - The protocol part of a URL, effectively always `https` for a production API. [06]
- **SCIM** - System for Cross-domain Identity Management: the standard for automatically provisioning and deprovisioning user accounts. [08]
- **scope** - A named permission attached to a token, such as `read:tickets`; missing scopes are why valid tokens receive 403 responses. [06]
- **SE academy** - A structured multi-month training and placement program for new solutions engineers; the strongest entry path without prior SE experience. [11]
- **self join** - joining a table to itself using two aliases, to compare rows within one table. [04]
- **server** - a computer elsewhere that holds data and logic and answers requests. [01]
- **service provider (SP)** - In single sign-on, the application a user is signing in to, meaning your product. [08]
- **SFTP** - SSH File Transfer Protocol: the encrypted file-drop mechanism behind most enterprise batch integrations. [08]
- **shell** - the program that reads and runs the commands you type in a terminal. [02]
- **signature** - A hash of a webhook payload computed with a shared secret and sent in a header, so the receiver can verify the sender. [08]
- **single-tenant** - each customer gets their own isolated copy of the application. [01]
- **Snowflake** - a cloud data warehouse; its SQL differs from PostgreSQL mainly in date and string functions. [03]
- **SOC 2** - An audit report on a vendor's security controls; Type II covers observed operation over a period and is what enterprise buyers want. [08]
- **solutions consultant** - Another name for a sales engineer, common at Salesforce, Workday, and ServiceNow; read the responsibilities, not the title. [11]
- **solutions engineer** - the technical person in a sales conversation, judged on explaining clearly and connecting systems accurately. [00]
- **SSO** - Single Sign-On: signing in once to a company identity provider and reaching every connected application without a separate password. [08]
- **staging area** - in Git, the set of changes selected for the next commit. [02]
- **STAR** - Situation, Task, Action, Result: the structure for a behavioral interview answer, with most of the time spent on Action. [11]
- **star schema** - one fact table surrounded by dimension tables, each one join away. [05]
- **status code** - the number in a response saying what happened: 200 worked, 401 unauthenticated, 404 not found, 500 server error. [01]
- **storage** - Cloud file storage addressed by bucket and key, such as AWS S3. [08]
- **subquery** - a query nested inside another query, in `WHERE` or `FROM`. [04]
- **success criteria** - Written, testable conditions agreed before a POC begins, which a neutral party could mark passed or failed. [10]
- **surrogate key** - a meaningless generated identifier, such as `customer_id`, used instead of a real-world value. [05]
- **table** - a set of rows with the same columns; the unit a database stores and a query reads. [03]
- **technical account manager (TAM)** - A post-sale role owning the technical relationship for a set of named accounts. [11]
- **technical buyer** - The person in a customer organization who can veto on technical grounds, and with whom an SE spends the most time. [10]
- **tell, show, tell** - The demo structure: state what you will show and why it matters, show exactly that, then confirm and hand back control. [10]
- **terminal** - the window where you type commands instead of clicking. [02]
- **traceback** - The Python error report printed when a script crashes; read it bottom-up, since the last line names what went wrong. [07]
- **URL** - the address a request is sent to. [01]
- **variable** - A name pointing at a value, in Python code or as a `{{placeholder}}` substituted from a Postman environment. (06, 07)
- **VS Code** - a free text editor for writing code, SQL, and Markdown. [00]
- **webhook** - A reverse API: you register a URL and the other system calls it the moment an event happens. [08]
- **window function** - a function computed across a set of related rows without collapsing them, written `f() OVER (...)`. [04]
- **working directory** - the folder a terminal is currently in; all relative paths are read from it. [02]
